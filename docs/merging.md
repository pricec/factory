# Merging: the normative merge-job procedure

This document is **normative** for merge jobs (spec §6.11). The factory's
merge queue dispatches one merge job at a time, pinned to the integration
foreman (`foreman:server`). The job's task text is generated by code
(`jobs.MergeTask`). It names the request and points here. A merge job
executes **this procedure exactly, every time**: every step, in order,
nothing added, nothing skipped. When a step says **STOP**, go straight to
[Reporting](#reporting) with status `failed`. The request then goes
`needs_attention`, and the factory routes it (see
[Who requests merges, and what happens when one fails](#who-requests-merges-and-what-happens-when-one-fails)).
Never improvise around a STOP.

Hard rules (they hold in every step):

- **Never touch the operator checkout `/home/price/temp/factory`.** It holds
  the operator's uncommitted work. Do not `cd` into it, and never run
  `checkout`, `switch`, `reset`, `stash`, `commit`, `clean`, `rebase` or
  `merge` there. The only allowed use is the read-only fetch in step 3, which
  reads it as a remote and writes nothing to it.
- **Never push to `master` directly, and never force-push anything**
  (`--force`, `--force-with-lease`, `+refspec`). Master changes only through
  `gh pr merge --merge`.
- **Work is never left unpushed.** If the requested commit exists only
  locally, push it to its branch before anything else (step 3).
- **Do not guess.** If the branch head does not match the request, STOP.

## 0. Inputs

The job payload carries the request. Set these shell variables from it.
Every command below uses them.

```sh
MR=<merge_request_id>      # e.g. mr_01J...
REPO=<repo>                # gh OWNER/REPO, e.g. pricec/factory
BRANCH=<branch>
HEAD_SHA=<head>            # 7-40 hex chars, as requested
NOTE=<note>                # PR title; may be empty
WORK=/tmp/factory-merge/$MR
EV=/var/lib/factory-foreman/evidence/merge-$MR
export PATH=/usr/local/go/bin:$HOME/go/bin:$PATH
mkdir -p "$EV"
```

## 1. Preflight

```sh
gh auth status && go version && sudo -n true
```

Any failure: **STOP** (`preflight: <what failed>`).

## 2. Dedicated clean clone

```sh
rm -rf "$WORK" && mkdir -p "$(dirname "$WORK")"
gh repo clone "$REPO" "$WORK" && cd "$WORK"
git fetch origin --prune
```

Every later command runs inside `$WORK`.

## 3. Verify the head; push the branch first if needed

```sh
REMOTE=$(git ls-remote origin "refs/heads/$BRANCH" | cut -f1)
# The requested commit, if it exists only locally: read-only fetch of the
# branch from the operator repository's object store (writes only to $WORK).
git fetch /home/price/temp/factory "refs/heads/$BRANCH:refs/local/$BRANCH" 2>/dev/null || true
LOCAL=$(git rev-parse -q --verify "refs/local/$BRANCH^{commit}" || true)
```

Decide, in this order:

1. `REMOTE` starts with `HEAD_SHA`. The branch is on origin at the requested
   head. Set `FULL=$REMOTE`.
2. `REMOTE` is empty, and `LOCAL` starts with `HEAD_SHA`. The branch is not
   on origin. **Push it first:** `git push origin "$LOCAL:refs/heads/$BRANCH"`.
   Set `FULL=$LOCAL`.
3. `REMOTE` is non-empty, `LOCAL` starts with `HEAD_SHA`, and
   `git merge-base --is-ancestor "$REMOTE" "$LOCAL"` succeeds. Origin is
   behind the requested head. Fast-forward it:
   `git push origin "$LOCAL:refs/heads/$BRANCH"` (never forced). Set
   `FULL=$LOCAL`.
4. Anything else is **head drift**: **STOP**
   (`head drift: requested $HEAD_SHA, origin/$BRANCH is ${REMOTE:-absent}, local is ${LOCAL:-absent}`).

Then confirm:

```sh
git fetch origin && test "$(git rev-parse "origin/$BRANCH")" = "$FULL"
```

If that fails: **STOP** (head drift).

## 4. Open (or reuse) the pull request

```sh
TITLE=${NOTE:-$BRANCH}
{ echo "Merge request $MR (factory merge queue, docs/merging.md)."; echo
  echo "Commits:"; git log --oneline --no-merges "origin/master..$FULL"; } > "$EV/pr-body.md"
PR=$(gh pr list -R "$REPO" --head "$BRANCH" --state open --json number -q '.[0].number')
[ -n "$PR" ] || PR=$(gh pr create -R "$REPO" --base master --head "$BRANCH" \
    --title "$TITLE" --body-file "$EV/pr-body.md" | grep -o '[0-9]*$')
test "$(gh pr view "$PR" -R "$REPO" --json headRefOid -q .headRefOid)" = "$FULL"
```

If the PR's head is not `$FULL`, **STOP** (head drift).

If `git log origin/master..$FULL` is empty, the branch is already merged.
**STOP** (`nothing to merge`).

## 5. Wait for green checks

Never trust an existing red verdict, and never declare the merge dead on
the first red. A red check on the head may be a one-off flake, and a
request re-queued at the same head would otherwise just re-read the
previous request's failed run. The deterministic gate (`internal/cigate`)
waits for the head's runs, and if any is red it re-runs the failed jobs
once (`gh run rerun <id> --failed`), waits for the fresh attempt, and only
then decides:

```sh
go run ./cmd/cigate -repo "$REPO" -sha "$FULL" | tee "$EV/cigate.json"   # exit 0 green, 1 red/no checks/timeout
gh pr view "$PR" -R "$REPO" --json mergeable,mergeStateStatus
```

Green means: `cigate` exits 0 (every run passed, at least one ran, possibly
after the one rerun) and `mergeable` is `MERGEABLE`. A rerun that turned
the head green is a **flake**: carry on, but report it (see Reporting).
Run `cigate` again only after pushing a new head (it reruns at most once
per call and never loops).

If `cigate` reports `red` (red in the rerun too), or the PR conflicts:

- **Small and clearly in scope.** The failure or conflict is in files the
  branch already changes, and the fix is a few lines with no contract or
  behavior change. Fix it in `$WORK` on the branch. Bring master in with
  `git merge origin/master`, never a rebase. Run `make ci`, then push the
  branch normally (no force). Go back to the start of step 5. Each extra
  commit goes in the report.
- **Anything else: STOP** (`checks red after rerun: <tests that failed both
  times>` or `conflict: <files>`). Never force-push. Never push to master.

## 6. Merge

```sh
gh pr merge "$PR" -R "$REPO" --merge --delete-branch=false
MERGED=$(gh pr view "$PR" -R "$REPO" --json mergeCommit -q .mergeCommit.oid)
git fetch origin && git merge-base --is-ancestor "$MERGED" origin/master
```

If `gh pr merge` refuses (branch protection, the branch moved), **STOP**.
Never retry with admin flags.

Only `pricec/factory` has a deploy procedure. For any other repo, skip to
step 8.

## 7. Deploy master

Run [docs/operator-runbook.md § Deploying master](operator-runbook.md#deploying-master)
exactly, with `REF=origin/master`. Its result must contain `$MERGED`
(check with `git merge-base --is-ancestor "$MERGED" "$DEPLOYED"`).
`$EV` is its evidence directory. The runbook's own failure steps (rollback
before the manifest) are part of this step. A deploy failure means
**STOP** (`deploy: <check that failed>; rolled back: yes|no`).

## 8. Verify and report

For `pricec/factory`, re-check right before reporting:

```sh
systemctl is-active factory
curl -fsS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8090/        # 200
go version -m /usr/local/bin/factory | grep -o 'buildinfo.ID=[^"]*'      # == build in dist/manifest.json
```

On success, `rm -rf "$WORK"`. On failure, leave it for the operator. Then
report.

## Reporting

Call `report_result` once, at the end:

- **done**: only when the PR is merged and, for `pricec/factory`, the deploy
  is verified healthy. `result.merged` must be `true`; the queue lands the
  request only then (a `done` without `merged:true` is `needs_attention`). Summary (240 chars max):
  `landed $MR: PR #<n> merged <MERGED:12>; deployed <build id>; exe sha ok, UI 200, journal clean`.
  `result`: `{merged: true, pr, merge_commit, deployed_commit, build_id, factory_exe_sha256, evidence_dir}`.
  If `cigate` reran and went green, add `ci_rerun: true` and `ci_flaked: [tests]`
  to `result` and append `; CI flake rerun: <tests>` to the summary, so flakes stay visible.
- **failed**: anything that stopped. The summary starts with the stage, for
  example `head drift: …`, `checks red after rerun: <tests failed both
  times>`, `conflict: …`, `deploy: …`. Also set **`result.stage`** to the
  stage that stopped, exactly one of `preflight`, `head_drift`,
  `nothing_to_merge`, `ci`, `conflict`, `merge`, `deploy`: the factory
  routes the failure on it (the summary prefix is only the fallback). For
  red checks, put the `cigate`
  output (`rerun`, `first_failed`, `second_failed`, `failed_both`) in
  `result` so the alert shows that a rerun happened and what failed.
  Always set `result.merged: false` and `result.reason` (e.g. `conflict`)
  when nothing was merged, and report `failed`, never `done`.
  `error`: `{"kind": "other", "message": "<stage>: <detail>"}`. Include
  `pr` / `merge_commit` in `result` when they exist, because a failure after
  the merge (in deploy) means master moved.

The merge request closes from this job's terminal state. Merge jobs start on the default tier; a `ci` or `conflict` failure is
re-run once on the hardest tier by the factory (spec §6.11). Merge jobs never
otherwise retry, and a merge job never fixes more than step 5 allows.

## Who requests merges, and what happens when one fails

This section is for everyone except the merge job (spec §6.11, "Job-owned
merges").

**The job that wrote the branch requests its merge.** A code-change job
works on a branch, gets CI green, pushes, and then calls the worker tool
`request_merge(branch, head, note?, after?)` itself, before it reports
done. The planner does not queue routine merges and does not have to
remember a follow-up. The operator can still queue a merge by hand (UI,
`POST /v1/merge-requests`), and the planner has `request_merge` for a
branch no job queued.

- `head` pins the commit: the merge job stops with head drift if the
  branch is anywhere else. A job that pushes one more commit calls
  `request_merge` again with the new head; its still-queued request is
  replaced. A request that is already merging is never replaced.
- `after` is the dependency gate: "queue this after branch X merges". The
  request stays queued, without blocking the queue, until a merge request
  for every named branch (same repo) has landed. Use it when the branch
  needs another job's branch on master first. If the dependency's merge
  fails for good or is cancelled, or nobody queues it within an hour, the
  planner is told: sequencing the work of different jobs is its
  coordination job.

**The factory tracks the outcome against the requesting job's task.**

| outcome | what the factory does |
|---|---|
| landed | Notes it on the task and wakes the planner once, to tell the operator. |
| failed, fixable by the branch's author: `ci`, `conflict`, `head_drift` | Dispatches a **merge-fix job** on the same branch, on the foreman that ran the requesting job, linked to the same task. It fixes, runs CI, pushes and calls `request_merge` again. No alert, no planner session. |
| failed, anything else: `deploy`, `preflight`, `merge`, `nothing_to_merge`, no report | P1 alert for the operator, linked to the task, and the planner is woken to coordinate. |
| failed after 2 merge-fix jobs | The same escalation. The loop is bounded: there is never a third fix job for one chain of requests. |

A request with no requesting job (operator, planner) fails as before: P1
alert, and re-requesting is the operator's call. Auditor auto-fixes keep
their own path (spec §6.12).

Nothing here changes the procedure above: every merge, whoever requested
it, is one merge job running steps 0 to 8, with the pinned head, the one
CI rerun and the deploy health check.
